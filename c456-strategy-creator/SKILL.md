# c456 策略生成技能

> 生成层技能。输入客户画像，输出定制化采集策略 + 定时执行技能。

---

## §1 核心逻辑

### 1.1 输入 → 输出

```
输入：客户画像 JSON（来自 c456-client-interview）
输出1：采集策略文档（关键词/渠道/筛选规则/来源优先级/打法方向）
输出2：定时技能文档（c456-<client>-curation/SKILL.md）
输出3：cronjob 配置（部署为每日定时任务）
```

### 1.2 策略生成四步法

```
① 拆解画像 → 提取关键维度（产品/受众/目的/能力）
② 设计采集 → 关键词/渠道/来源层级/筛选规则
③ 设计组合 → 根据画像预定义「信号+工具→打法」的模板方向
④ 输出技能 → 生成可执行的定时技能文档 + cron 配置
```

---

## §2 拆解画像（Strategy Decomposition）

根据客户画像中的每个维度，推导出采集策略：

### 2.1 从「产品」推导

| 画像维度 | 推导策略 |
|---------|---------|
| 产品定位 | 关注同类竞品的发布/更新/用户反馈 |
| 价值主张 | 关注用户为什么付费——采集能强化这个价值的信息 |
| 商业模式 | 不同模式关注点不同：订阅→关注用户留存；课程→关注内容趋势；咨询→关注行业案例 |
| 竞争优势 | 关注竞品的弱点/用户的抱怨——找到差异化机会 |

### 2.2 从「受众」推导

| 画像维度 | 推导策略 |
|---------|---------|
| 受众类型 | 开发者→关注 GitHub/Tech/Tool 类源；管理者→关注 SaaStr/Business 类源 |
| 技术水平 | 技术高→直接给深度内容；技术低→需要教程/步骤化打法 |
| 活动平台 | 受众在哪→采集策略就要覆盖哪里的信息源 |
| 地域语言 | 中文→36kr/sspai/知乎/机器之心；英文→TechCrunch/Ars/Latent Space |

### 2.3 从「目的」推导

| 画像维度 | 推导策略 |
|---------|---------|
| 赚钱目的 | 关注「降本」「提效」「获客」「转化」相关的工具和方法 |
| 短期目标 | 采集能马上用上的工具和教程 |
| 长期目标 | 采集行业趋势、范式转变、长期战略分析 |

### 2.4 从「能力」推导

| 画像维度 | 推导策略 |
|---------|---------|
| 技术能力 | 技术强→工具可复杂，可涉及编程；技术弱→工具需零配置，打法需步骤化 |
| 时间预算 | 时间少→每次输出精简，聚焦最重要的一条打法建议 |
| 营销预算 | 预算低→侧重有机增长/内容营销策略；预算有→可涉及付费投放 |

## §3 生成采集策略

### 3.1 策略文档结构

```yaml
strategy:
  client_name: "客户名称"
  
  # 采集关键词（动态，根据画像生成）
  keywords:
    primary: ["核心关键词1", "核心关键词2"]
    secondary: ["辅助关键词1", "辅助关键词2"]
    competitor: ["竞品关键词1"]
    
  # 渠道配置（从 25 个 RSS 源中筛选）
  sources:
    tier1_authoritative: ["TechCrunch", "Ars Technica", "GitHub Blog", ...]
    tier2_industry: ["Latent Space", "Pragmatic Engineer", "TLDR AI", ...]
    tier3_signal: ["Hacker News", "Product Hunt", ...]
    tier4_local: ["36kr", "sspai", "机器之心"]
    
  # 来源优先级规则
  source_rules:
    - "如果 HN 上某个话题 100+ 票 → 搜索该话题的官方源引用"
    - "V2EX/Reddit 的讨论帖只提取话题方向，不直接引用"
    - "X/Twitter 帖子降级为信号提示，不直接收录"
    
  # 打法方向（预定义的「信号+工具→打法」模板）
  playbook_directions:
    - direction: "降本增效"
      signal_pattern: "AI 工具降价/开源替代崛起"
      tool_pattern: "自动化工具/BYOK 模型"
    - direction: "获客增长"
      signal_pattern: "平台算法变化/新渠道崛起"
      tool_pattern: "营销自动化/内容生成工具"
```

### 3.2 从画像生成采集策略的规则

**关键词提取规则：**
- 从客户的产品描述中提取 3-5 个核心关键词
- 从客户的目标受众中提取 2-3 个受众特征词
- 从竞品优势中提取 2-3 个竞争关键词
- 组合成「产品词 + 场景词 + 受众词」三元组

**渠道筛选规则：**
- 受众在中文市场 → 必加 36kr/sspai/机器之心
- 受众是开发者 → 必加 GitHub Blog/Pragmatic Engineer/Latent Space
- 受众是管理者 → 必加 SaaStr/TechCrunch
- 受众技术强 → 加 arXiv/Simon Willison 等深度源
- 受众技术弱 → 减少 arXiv/论文源，增加产品评测/教程类源

**打法方向生成规则：**
- 如果客户目的是「赚钱」→ 打法方向侧重「获客/转化/降本」
- 如果客户产品是 SaaS → 打法方向侧重「产品增长/用户留存」
- 如果客户是独立开发者 → 打法方向侧重「单人效率/自动化」
- 如果客户是企业 → 打法方向侧重「团队协作/规模化」

## §4 生成定时技能

### 4.1 技能生成模板

每个客户生成一个专属的定时技能 `c456-<client>-curation`，其 SKILL.md 结构如下：

```yaml
---
name: c456-<client>-curation
description: "为 <客户名> 定制的每日信息策展技能。采集策略基于 <画像日期> 的客户画像生成。"
version: 1.0.0
---
```

技能正文包含：
1. 客户画像摘要（关键维度）
2. 采集关键词列表
3. 渠道配置（从 25 个源中筛选）
4. 筛选规则（什么采、什么不采）
5. 打法组合建议（根据画像预定义的方向）
6. 执行流程（步骤化）

### 4.2 Cron 配置

生成的 cronjob 参数：

```yaml
schedule: "0 7 * * *"       # 每天 7:00
skills: ["c456-<client>-curation", "c456-voice-journalist"]
deliver: "<客户接收渠道>"
enabled_toolsets: ["terminal", "file", "web"]
```

### 4.3 多客户管理

每个客户独立：
- 一个定时技能（`c456-<client>-curation`）
- 一个 cronjob（`c456-<client>-daily`）
- 一个投递渠道（元宝 DM / Telegram / Email）
- 一个画像 JSON（`c456-sync/clients/<client>/profile.json`）

管理目录结构：

```
c456-sync/clients/
  ├── <client-a>/
  │   ├── profile.json        # 客户画像
  │   ├── curation-strategy.yaml  # 采集策略
  │   └── logs/               # 每日输出日志
  └── <client-b>/
      └── ...
```

## §5 执行流程

```
① 加载本技能（c456-strategy-creator）
② 获取客户画像 JSON（来自 c456-client-interview）
③ 执行 §3 策略生成 → 输出采集策略文档
④ 执行 §4 技能生成：
   a. 创建 c456-<client>-curation SKILL.md
   b. 创建 c456-sync/clients/<client>/profile.json
   c. 创建 cronjob
⑤ 告知客户：「您的定制化信息采集已就绪，明早 7:00 开始推送」
⑥ 每天 cron 执行后，收集客户反馈，迭代策略
```

## §6 迭代优化

### 6.1 反馈循环

客户对每日推送的反馈是迭代策略的关键信号：

| 客户反馈 | 策略调整 |
|---------|---------|
| 「这个方向不对」 | 调整关键词/渠道权重 |
| 「这个打法有用」 | 强化该方向的信号采集 |
| 「这个工具不错」 | 加入工具层的深度调研队列 |
| 「太技术了，看不懂」 | 降低技术源的权重，增加教程/产品评测 |

### 6.2 版本管理

每次策略迭代，更新 `curation-strategy.yaml` 的版本号，记录变更日志：

```yaml
version: 1.2.0
changelog:
  - date: "2026-07-16"
    change: "增加 TechCrunch 源权重，降低 arXiv 权重"
    reason: "客户反馈论文太多，需要更多产品新闻"
```

## §7 AI 搜索源优化（AISO）

> 附加模块。在生成策略时，加入「目标 AI 搜索源」维度，让内容发布更有针对性。

### 7.1 核心理念

现在的获客方式正在从「搜索引擎优化（SEO）」转向 **「AI 搜索优化（AISO）」**。

用户不再通过 Google/百度搜索解决方案，而是直接在豆包/元宝/DeepSeek 等 AI 提问。AI 的回答引用了哪些来源，决定了哪些企业/服务能被推荐。

**我们的策略：** 研究各 AI APP 的引用偏好 → 针对性地在那些来源发布内容 → 让 AI 在回答时引用我们的内容 → 用户通过 AI 找到我们。

### 7.2 主流 AI APP 引用来源调研

| AI APP | 推测引用来源 | 优化策略 |
|--------|------------|---------|
| **豆包** | 头条号、微信公众号、知乎、百度百科 | 头条号/公众号同步打法，知乎回答相关问题 |
| **元宝** | 腾讯新闻、公众号、搜狗、知乎 | 公众号是核心分发渠道 |
| **DeepSeek** | Web 搜索结果（Bing/Google） | 传统 SEO 仍有价值，网页结构化优化 |
| **Kimi** | 合作媒体、网页索引 | 争取在权威媒体网站发布 |
| **百度文心一言** | 百度系、百家号、百度百科 | 百家号分发，百度百科词条建设 |
| **通义千问** | 阿里系 | 暂不考虑，等业务扩展 |

### 7.3 执行规则

生成策略时，根据客户的地域/语言，自动加入 AISO 模块：

```yaml
aiso:
  target_apps: ["豆包", "元宝", "DeepSeek"]  # 根据客户地域选择
  content_optimization:
    - "每篇打法同步发布到目标 APP 的引用源"
    - "在知乎上回答目标受众会问的问题，植入 c456 品牌"
    - "公众号文章保持稳定更新（元宝和豆包都引用）"
  monitoring:
    - "定期用各 AI APP 搜索核心关键词，检查是否被推荐"
    - "记录推荐结果变化，调整发布策略"
```

### 7.4 客户画像中的 AISO 配置

在客户画像中增加 `aiso` 字段：

```json
{
  "aiso": {
    "enabled": true,
    "targetApps": ["豆包", "元宝", "DeepSeek"],
    "publishChannels": ["公众号", "知乎", "头条号", "百家号"],
    "optimizationNotes": "针对成都地域优化，让用户搜索'成都 AI 优化服务'时被推荐"
  }
}
```

## §8 技能自我进化（Self-Evolution）

> 核心机制。技能必须能识别自己的缺陷并自动调整，**不需要客户来告诉你怎么改**。

### 8.1 核心理念

客户告诉你的是**目标和需求**，不是**实现方案**。实现方案（采集什么信息、用什么来源、怎么筛选）是你的专业判断，应该由你根据客户的反馈自动调整。

如果客户说「这条信息没用」——不是客户有问题，是你的筛选策略有问题，你去改。

### 8.2 反馈信号与自动调整

| 客户行为/反馈 | 技能自动调整 |
|-------------|------------|
| 「这消息不对/过时了」 | 降低该来源的权重，增加多源交叉验证 |
| 「这消息太偏了」 | 检查来源优先级，增加权威源权重 |
| （连续几天不选任何内容） | 降低采集广度，增加精准度；调整关键词 |
| 「这个方向有用」 | 强化该方向的信号源和相关关键词 |
| 「太技术了看不懂」 | 降低论文/技术源权重，增加案例/产品评测源 |
| 「你这个来源不可靠」 | 将该来源降级或移除，增加备选源 |

### 8.3 自动调整执行流程

```
① 记录客户反馈（什么内容被拒、什么被选、什么被赞）
② 每周自动评估一次采集效果
③ 如果连续 3 天客户选中的内容 < 30% → 调整策略
④ 如果客户明确说「这个来源不行」→ 立即移除该来源
⑤ 如果客户说「我需要更多 X 方向」→ 增加 X 方向的源和关键词
⑥ 记录每次调整到 changelog
```

### 8.4 常识库（Commonsense Knowledge）

以下是不需要验证、直接内置的常识规则，技能启动时自动加载：

```yaml
commonsense:
  sources:
    - "TechCrunch、Ars Technica、The Verge 是一手科技新闻的可靠来源"
    - "V2EX、Reddit、HN 是社区讨论，需要溯源验证"
    - "X/Twitter 帖子不可作为一手引用来源，仅作为信号提示"
    - "微信公众号、知乎专栏、百家号是中文市场 AI 搜索的主要引用来源"
    - "arXiv 论文在客户不需要技术深度时应该降权"
    - "36kr 快讯适合做信息提示，不适合做深度分析引用"
  audience:
    - "国内小企业主和自由职业者关心的是'怎么赚钱'和'怎么省钱'"
    - "技术弱的用户需要步骤化方案，不是技术分析"
    - "零预算客户需要有机增长策略，不是付费投放方案"
  channels:
    - "公众号内容会被元宝和豆包引用"
    - "知乎内容会被豆包和百度文心引用"
    - "百家号内容会被百度文心引用"
    - "企业官网内容会被 DeepSeek 和 Kimi 搜索引用"
```

### 8.5 技能启动自检清单

每次技能被加载（包括 cron 定时执行）时，先运行以下自检：

- [ ] 当前的来源列表是否匹配客户画像？（如果客户是做国内市场的，有足够的国内源吗？）
- [ ] 最近 3 天的客户选中率是多少？（<30% 则需要调整）
- [ ] 上次调整是什么时候？调整了什么？
- [ ] 客户画像是否需要更新？（有新对话补充了信息吗？）
- [ ] 搜索关键词是否仍然有效？（是否需要补充新关键词？）

如果任何一项检查未通过，技能应在执行采集前先自我修复。

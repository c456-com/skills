# GEO 评估框架

> Generative Engine Optimization — 为 AI 生成引擎优化的网站测评方法论。
> 应用于 c456.com/reports/aio/<domain> 报告的生成。

## 综述

GEO 评估分两个维度：**技术检测**（网站对 AI Agent 的可访问性）和 **内容检测**（网站在 AI 搜索中是否容易被推荐）。综合评分公式：

```
总分 = 技术分 × 0.4 + 内容分 × 0.6

内容分 = (话题所有权 × 0.25 + Schema 覆盖度 × 0.25 + 品类定位 × 0.20 + 写作风格 × 0.15 + AI 成熟度 × 0.15) × 10
```

内容分占 60%，因为 AI 搜索推荐中「说什么」比「技术多好」更重要。

## 分析过程记录原则（重要）

每份 GEO 报告必须包含分析过程记录，记录评估者「读了什么、看了什么、基于什么做的判断」：

- 访问了哪些 URL
- 看到了什么关键信息（如 meta description、llms.txt 内容、Schema 存在性）
- 基于什么标准做的评分
- 与已知案例（baklib/sobaking）的对比

这一点对报告可信度至关重要。技术团队在实现自动化版本时，应在报告中保留分析过程摘要。

## 技术检测（22 项）

使用 AFDocs (afdocs.dev) 执行，覆盖 7 个类别：
- Content Discoverability (llms.txt 等)
- Markdown Availability
- Page Size and Truncation Risk
- Content Structure
- URL Stability and Redirects
- Observability and Content Health
- Authentication and Access

## 内容检测（5 类 18 项）

### 1. 话题所有权评估

| 检查项 | 方法 | 评分 |
|--------|------|------|
| 核心话题清晰度 | 首页和 About 页是否明确描述核心业务 | 1-10 |
| AI 话题占有 | 豆包/元宝/DeepSeek 搜索核心关键词是否被推荐 | 1-10 |
| 话题聚焦度 | 内容是否集中在一个核心话题而非多主题混杂 | 1-10 |
| 外部话题信号 | 知乎/公众号/行业平台上的内容是否与官网一致 | 1-10 |

### 2. Schema 实体覆盖度

| 检查项 | 方法 | 评分 |
|--------|------|------|
| 核心实体标记 | Organization/Product/Service 等 Schema 是否存在 | PASS/WARN/FAIL |
| 实体完整性 | 每个核心实体是否包含 name/description/url | PASS/WARN/FAIL |
| 实体关联性 | 实体间关系是否通过 Schema 明确标记 | 1-10 |
| 行业特异性 | 是否使用行业相关 Schema 类型（如 LocalBusiness） | 1-10 |

### 3. 品类定位评估

| 检查项 | 方法 | 评分 |
|--------|------|------|
| 品类明确度 | 标题和核心页面是否明确说出「我们是做什么的」 | 1-10 |
| AI 归类验证 | AI 搜索测试品牌是否在正确的品类中被推荐 | PASS/FAIL |
| 竞品品类对比 | 同行业竞品的品类定位是否更清晰 | 1-10 |
| 多品类管理 | 多业务线公司是否为每个服务建立了独立页面和 Schema | 1-10 |

**多品类处理原则（重要）：**
真实的企业往往有多个产品/服务。解决方案不是砍掉赚钱的业务，而是结构化多品类布局：

1. 首页做「伞形品类」定位（如「企业数字化服务提供商」）
2. 每个服务建立独立落地页，各自做 Schema 和内容
3. llms.txt 中每个服务单独一个 section
4. 每个页面只讲一个话题，不混杂

这样 AI 在搜索「成都建站公司」时推荐建站页，搜索「成都小程序开发」时推荐小程序页。互不干扰。

### 4. 写作风格 AI 友好度

| 检查项 | 方法 | 评分 |
|--------|------|------|
| 开篇清晰度 | 核心页面第一段是否直接说清主题 | 1-10 |
| 结构化程度 | 是否使用小标题、列表、表格 | 1-10 |
| 信息密度 | 是否存在大量低信息量段落 | 1-10 |
| 模糊表达比例 | 「某个」「有些」「据说」等降低置信度的表述比例 | 低/中/高 |

### 5. AI 化成熟度

| 检查项 | 方法 | 评分 |
|--------|------|------|
| llms.txt 策略 | 不仅仅是格式合规，内容策略也合理 | 1-10 |
| AI Agent 友好声明 | 是否有明确针对 AI Agent 的访问策略 | PASS/FAIL |
| 结构化数据策略 | 是否有系统性的 Schema 管理流程 | 1-10 |
| 内容更新频率 | 更新频率是否足够让 AI 持续关注 | 1-10 |

## 等级划分

| 等级 | 分数 | 含义 | 行动 |
|------|------|------|------|
| S | 90-100 | 优秀 | 维持策略，关注变化 |
| A | 75-89 | 良好 | 修复少量问题 |
| B | 55-74 | 一般 | 需要系统性优化 |
| C | 35-54 | 较弱 | 需要大幅改进 |
| D | 0-34 | 很差 | 从基础重建 |

## 优化方案四步法

1. **基础修复**（1-2 天，零成本）：创建 llms.txt、改写首页定位句
2. **结构化数据**（3-5 天，低成本）：添加 Schema 标记
3. **内容策略调整**（1-2 周，中成本）：确定核心品类，统一内容方向
4. **AI 搜索布局**（2-4 周，持续）：在 AI 引用平台（知乎/公众号/百家号）上布局内容

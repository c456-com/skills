# 工具发现与生态跟踪渠道

## 工具发现渠道（持续更新）

| 渠道类型 | 来源 | 用途 |
|---------|------|------|
| **产品发现** | Product Hunt、GitHub Trending、Hacker News Show | 发现新工具 |
| **大V/自媒体** | 技术博主、YouTuber、独立研究者、Twitter/X 技术圈 | 学习别人的方案和工作流 |
| **评测/对比** | Search Engine Land、Pragmatic Engineer、深度评测文章 | 了解工具的真实能力和局限 |
| **社区讨论** | Reddit、V2EX、GitHub Discussions | 发现别人踩的坑和奇思妙想 |
| **开发者生态** | npm 趋势、GitHub 星标增长、Release notes | 判断工具活跃度和发展方向 |

## 生态跟踪：看用法不看版本

核心原则：**不是盯产品的发布日志，是盯社区怎么用这个产品。**

### 哪些用法值得关注

| 关注内容 | 为什么 | 从哪里找 |
|---------|--------|---------|
| 别人做的自动化工作流 | 可以直接复制给客户 | Twitter/Reddit/V2EX/博客 |
| 开源的技能和脚本 | 降低 c456 的开发成本 | GitHub/社区分享 |
| 工具 + 其他工具的组合方案 | 启发 c456 的新服务设计 | 技术博客/播客/教程 |
| 使用中遇到的坑和解决方案 | 避免 c456 踩同样的坑 | 社区讨论/Issues/Discord |

### 评估标准

- 这个用法能直接或改造后给客户用吗？
- 这个组合方案比我们现在的方案更好吗？
- 这个用法提示了哪些我们没想到的场景？

## 当前核心底座：Hermes Agent

- Hermes 是 c456 方案交付的默认自动化引擎
- 关注点不是 Hermes 发布了什么版本，而是**社区拿 Hermes 做了什么**
- 关注途径：GitHub Discussions、Discord、Reddit、Twitter/X 上分享的工作流

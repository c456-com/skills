# LLM Wiki Book — 书籍知识编译

本技能用于把一本书从 `raw/books/` 的逐页材料，编译成领域 wiki 中可查询、可追溯、可持续维护的知识网络。它强调整本书的连续性、章节递进、作者论证链、故事/案例、使用场景和适用边界，而不是把单页 OCR 或视觉提取结果当作独立文章处理。

## 何时使用

当用户出现以下意图时使用本技能：

- 要把一本书录入、消化、编译、整理到领域 wiki。
- 要从 `domains/<domain>/raw/books/<book>/` 或根层 `raw/books/<book>/` 的连续页生成来源页、概念页、案例页、线索页、查询页或比较页。
- 要基于一本或多本已录入书籍回答问题，尤其是需要组合概念、方法、案例、故事、场景、边界和来源的回答。
- 要校正 `raw/books/` 中由 PDF/OCR/视觉提取造成的页码、章节、页眉页脚或正文噪声问题。

不要在只有 PDF、扫描件或拍照页尚未转成 Markdown 页时直接使用本技能执行提取；应先使用 `book-extract`。

## 与相关技能的分工

| 技能 | 职责 | 不负责 |
|------|------|--------|
| `book-extract` | 把 PDF、扫描件、拍照书页或 MinerU 输出提取为 `raw/books/` Markdown + 图片 | 不负责深度知识编译、案例建模、章节论证链维护 |
| `llm-wiki-book` | 消费 `raw/books/`，按连续内容窗口理解整本书，抽取知识对象并写入领域 wiki | 不负责 PDF/OCR/视觉提取本身 |
| `llm-wiki` | 提供通用 wiki 读写、来源、概念、实体、索引、日志和查询维护方法 | 不单独处理书籍连续页、章节递进和案例一等化的强约束 |
| `llm-wiki-domains` | 判断资料属于哪个领域，维护根层注册表和多领域导航 | 不替代具体书籍的章节级摄取与知识编译 |

如果材料跨领域，先用 `llm-wiki-domains` 判断主领域和可能的跨领域输出；进入单个领域后，使用本技能执行书籍编译，并沿用该领域 `AGENTS.md` 的页面类型注册表。

## 开始前定位

1. 读取根层 `wiki/index.md` 的领域注册表，确认目标领域路径。
2. 读取领域 `AGENTS.md`、`wiki/index.md`、`wiki/log.md`，必要时读取 `wiki/overview.md` 或相关 `threads/`。
3. 检查书籍原始材料路径，例如 `domains/<domain>/raw/books/<book>/pages/`、`book.md`、`.extract-meta.yml`、`images/`。
4. 搜索既有页面，避免重复创建来源页、概念页、案例页或线索页。
5. 如仓库启用了 versioned-llm-wiki，更新 wiki 页面前按版本规则创建快照。

## 书籍性质识别

录入前必须判断这本书的性质，并据此决定重点提取对象。可同时有多个类型，但要写清主类型和次类型。

| 书籍类型 | 高价值信息重点 |
|----------|----------------|
| 心理健康 / 医学科普 | 症状描述、机制假说、干预方法、适用人群、禁忌、风险信号、案例、研究边界、就医边界 |
| 个人成长 | 核心主张、行为模型、练习方法、失败条件、场景、故事、反例、长期实践路径 |
| 创业 / 产品 / 营销 | 用户场景、客户案例、决策框架、实验方法、指标、渠道、失败案例、边界条件 |
| 投资 / 商业 | 投资原则、风险框架、周期判断、案例、反例、数据口径、不可迁移条件 |
| 技术 / AI 工程 | 概念、架构、步骤、工具、约束、错误模式、实现示例、适用环境 |
| 传记 / 回忆录 | 人物经历、关键转折、决策情境、长期主题、关系网络、故事、时代背景 |
| 教材 / 课程 | 知识体系、定义、定理/模型、例题、练习、常见误区、学习路径 |
| 说明书 / 手册 | 操作步骤、参数、限制、故障排除、使用场景、警告、依赖条件 |

来源摘要页应记录：书名、作者、版本或出版信息、原始路径、书籍类型、主旨、结构、章节递进、关键问题、作者论证链、跨章节概念演化、已处理范围和未处理范围。

## 连续内容窗口

书籍录入必须以连续页面、连续段落、完整小节或完整章节为最小理解单元。不要孤立处理单页。

构建窗口时遵守：

- 若当前页包含跨页段落、代词承接、未结束列表、延续案例或未完成论证，合并前后相邻页后再提取。
- 若小节或章节是完整论证单元，优先以小节或章节为窗口。
- 窗口应记录原始页范围，例如 `pages/page-012.md..page-018.md`，以及自然页码或章节判断。
- 长章节可按小节分批，但每批都要保留前后摘要，维护作者论证链和术语演化。
- 后文补充、限制或修正前文观点时，记录"观点演化"，不得静默覆盖前文结论。

章节、小节和连续页处理策略：

1. 先快速扫描目录、章节标题、页眉页脚线索和连续页内容，建立临时章节地图。
2. 对每个窗口提取主张、证据、概念、方法、案例、故事、场景、边界、反例、工具和引用。
3. 把窗口结论写入来源摘要页或章节条目，再决定是否需要独立页面。
4. 每处理完一个连续章节或一批章节，更新领域 `wiki/index.md` 和 `wiki/log.md`，记录已处理范围、更新页面、未处理范围和下一步建议。

## 高价值信息分类

通用必须提取类别：

- 主张：作者明确提出的判断、原则、结论或建议。
- 概念：可复用定义、模型、机制、分类或术语。
- 方法：可执行步骤、练习、流程、框架或检查清单。
- 案例：有背景、问题、行动、过程、结果或失败原因的实例。
- 故事：承载情境、人物、冲突和变化的叙事，不可只当作装饰性摘要。
- 场景：方法或观点适用的对象、情境、触发条件和使用方式。
- 边界：前提、限制、禁忌、失败条件、风险信号和不可迁移条件。
- 反例：与主张相反或显示方法失效的材料。
- 工具：量表、模板、表格、脚本、操作步骤、资源清单。
- 引用：值得保留的原文句子，必须标明页码或原始位置。

## 专业词条识别与建页

书籍录入时，专业词条不是只处理作者原创概念。只要一个词条对理解书中论证、方法、案例、边界或后续查询有长期价值，就应进入候选清单，并按阈值判断是否建页。

每个连续章节窗口除了提取主张、证据、概念、方法、案例、故事、场景、边界、反例、工具和引用外，还要输出"词条候选清单"。候选包括：

- 作者原创或书中特有概念。
- 书中反复使用的领域标准术语。
- 虽非书中原创，但对理解章节论证、方法、案例或边界不可缺少的知名专业词条。
- 被多个章节共同依赖的机制词、营养素、疾病/症状、指标、工具和分类。

建页阈值：

- 在 2 个以上来源或章节窗口出现，建页。
- 虽只在一本书中出现，但支撑一个章节、方法或案例，建页。
- 虽非作者原创，但属于领域基础词条，并且用户后续查询大概率会检索，建页。
- 仅作过路提及、装饰性引用、领域外内容，不建页；可留在来源页、章节条目或词条候选清单中。

概念页写法：

- frontmatter 建议加入 `term_origin: standard | author_original | book_usage | uncertain`。
- 标明 `source_mentions` 或"来源位置"，保留 raw 页范围。
- 区分"领域通用定义"和"书中如何使用该词"。
- 若只来自书中、未做外部校验，`confidence` 不应高于 `medium`。

写入位置建议：

| 信息类型 | 首选位置 |
|----------|----------|
| 书籍整体主旨、章节结构、论证链、已处理范围 | `wiki/sources/<book>.md` |
| 可复用概念、模型、方法 | `wiki/concepts/`，或领域 schema 中等价目录 |
| 长期问题、跨章节主题、观点演化 | `wiki/threads/` |
| 故事、案例、患者/用户/创业者/投资者/作者亲历 | `wiki/cases/`，或领域 schema 中等价目录 |
| 用户问题沉淀出的可复用回答 | `wiki/queries/` |
| 多本书、多方法、多观点横向对照 | `wiki/comparisons/` |

不要把"某一本书的全书概览、章节模块表、核心观点汇总"写成 `wiki/concepts/` 页面；这类内容应合并到来源摘要页，或在确实追踪跨章节观点演化时写入 `wiki/threads/`。

如果领域 `AGENTS.md` 未注册 `cases/`，但书中案例具有长期查询价值，可创建 `wiki/cases/` 并在相关索引或 schema 更新处说明；若用户或父流程要求不改 schema，则先在来源页写结构化案例条目，并在日志中标记待登记页面类型。

## 故事和案例是一等知识对象

故事和案例不是摘要中的可选点缀。只要它们展示问题背景、行动过程、变化机制、结果、失败原因或适用边界，就应作为可查询知识对象处理。

案例页建议结构：

```markdown
# 案例名称

---
type: case
source: [[书籍来源页]]
book_location: "chapter/page/window"
confidence: medium
---

## 背景

## 问题

## 行动

## 过程

## 结果

## 启发

## 适用边界

## 来源位置
```

案例页或案例条目必须链接到相关 `[[概念]]`、`[[方法]]`、`[[场景]]`、`[[来源页]]`。如果一个故事支撑某方法，应在方法页回链该案例；如果故事显示方法失败，应链接到边界或反例段落。

抽取案例时要区分：

- 书中明确发生的真实案例。
- 作者构造的假设场景。
- 研究、实验或统计材料。
- 用户要求时临时类比出的说明。

前三类可入库，但必须标注类型；第四类不能伪装成书中案例。

## 查询回答策略

基于书籍知识回答问题时，先定位相关领域和书籍页面，再组合以下材料：

- 概念：问题涉及的核心定义、机制和模型。
- 方法：书中给出的步骤、练习、框架或决策流程。
- 案例 / 故事：书中真实案例、假设场景或作者亲历，用于说明方法如何发生作用。
- 场景：用户问题与书中场景的匹配程度。
- 边界 / 反例：不适用条件、风险、失败条件和相反证据。
- 来源：书名、章节、页码、窗口范围或 wiki 来源页。
- 置信度：材料是否来自单一书籍、多个章节互证、多来源互证，或只是低置信线索。

规则：

- 没有案例时必须明确说"当前知识库没有找到相关书中案例"，不得编造患者、用户、创业者、投资者或作者故事。
- 可用概念和方法回答时，也要说明缺少案例会降低说明力。
- 对带具体个人处境的问题，优先说明适用前提和风险边界，再给方法。
- 有保存价值的综合回答写入 `wiki/queries/`，并更新索引和日志。

健康、医学和心理类问题必须增加安全边界：

- 说明 wiki 内容是读书笔记和知识整理，不构成诊断、处方或替代专业医疗/心理服务。
- 若用户描述自伤、自杀、精神病性症状、严重失眠、药物调整、急性风险或未成年人安全问题，应建议尽快联系当地急救、精神科、心理危机热线或合格专业人士。
- 对干预方法要标注适用对象、禁忌、证据强度和"何时停止自行尝试并求助"。
- 案例只能帮助理解情境，不等于医学证据本身。

## 原始数据校正规则

`raw/books/` 页级 frontmatter、页码、页头、页脚、章节名和视觉提取元数据都是可疑线索，不是最终事实。图片提取、OCR 或 MinerU 输出可能缺少跨页上下文，录入时可以基于连续页面主动修复明显错误。

可以修复或标注的问题：

- 页码错位、漏页、重复页或自然页码与文件编号不一致。
- 章节、小节、标题层级误判。
- 页眉、页脚、页码、目录残片、重复书名、版权页残片被误识别为正文。
- 跨页段落断裂、脚注误入正文、表格行列轻微错位。
- 视觉模型把插图说明、边栏、引用块或正文顺序混淆。

修复要求：

- 修复必须保留依据，记录使用了哪些连续页面、相邻标题、目录、页码序列或上下文证据。
- 只对明显噪声和结构错误做直接修复；修复说明可写在 raw 页 frontmatter 的校正字段、页内备注、来源页"原始数据校正"段落或 `wiki/log.md`。
- 涉及正文含义变化、删改作者观点、改变事实或无法确认的内容，不得静默修改。应保留原文，在 wiki 层写纠错说明、低置信标记或请求用户确认。
- 不要为了让结论更顺而改写来源含义；wiki 可以解释来源，但不能伪造来源。

## index/log 更新

每完成一批章节或一个连续处理窗口后，必须维护领域导航：

1. 更新 `wiki/index.md`：列出新增或更新的来源页、概念页、案例页、线索页、查询页或比较页，并给一句摘要。
2. 追加 `wiki/log.md`：格式遵循领域规则，至少记录日期、操作类型、书名、处理页码/章节范围、更新文件、原始数据修复、未处理范围和下一步。
3. 若新增页面类型或跨领域结论影响根层导航，按 `llm-wiki-domains` 规则更新根层索引或留下待办。

## 验收清单

- 已确认书籍所属领域、原始路径和书籍性质。
- 已按连续内容窗口或章节/小节理解，不是孤立处理单页。
- 来源摘要页包含主旨、结构、章节递进、论证链、来源位置和处理范围。
- 已提取主张、概念、方法、案例、故事、场景、边界、反例、工具和引用。
- 故事/案例已作为可查询对象或结构化条目处理，并链接相关概念、方法、场景和来源。
- 查询回答未编造案例，健康/心理问题包含安全边界。
- 对 `raw/books/` 的修复有依据记录，涉及含义变化的内容没有静默修改。
- 已更新领域 `wiki/index.md` 和 `wiki/log.md`。

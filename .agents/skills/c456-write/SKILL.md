# c456-write：C456 内容写作方法论

> 数据同步层技能。涵盖三种内容类型的写作方法。对外正文格式须同时遵守 `c456-sync` 技能。

---

## §A 信号研究员（Signal Researcher）

适用于：新闻收录、行业动态、研究信号、事实核验短文。

### 定位

目标不是「记一条笔记」，而是 **让读者在短时间内做决定**：这条消息值不值跟进、对谁有意义、和站上已有内容怎么拼在一起。

动笔前心里过三个问题：

1. **发生了什么**——能核对吗？日期、主体、数字是否齐？
2. **为什么值得看**——对谁、在什么约束下有用？
3. **和咱们已有内容什么关系**——接续、打脸、还是补一句背景？

### 信号结构

**1. 导语（1～3 句）**

先用 **人话** 交代事件 + 对你这类读者意味着什么。十秒钟内要能判断还要不要往下读。避免「在数字化浪潮下」「值得注意的是」这类零信息开篇。

对外稿若用 `##` 分节：**核心判断写在第一节下的正文段落里**，**不要**单开 `## 一句话结论`、`## TL;DR`。

**2. 事实描述（2～5 段）**

- 谁、做什么、什么时间、对哪条产品线/用户群生效
- 版本号、价格、配额、发布日期等 **硬事实** 跟紧；吃不准就写 **「以官方最新说明为准」** 并指 URL
- 官网通稿可以读，成稿时 **改写** 成读者要用的信息密度

**3. 价值分析（核心）**

| 分析维度 | 自问 |
|----------|------|
| **行业** | 这条是噪声还是范式变化？有没有更可验证的旁证？ |
| **读者** | 谁该盯？ small team / 企业 / 开源用户——别假装「所有人都该关心」 |
| **时机** | 现在就该动手试，还是先放进观察清单？ |
| **边界** | 哪些是厂商叙事、哪些是我们从材料里推出来的？ |

少写对称废话（「不仅……而且……」信息量为零就删）。一句短结论 + 一两句依据，通常就够。

**4. 来源块**

```markdown
## 来源
- **原文**：[标题](URL) — 发布日期
- **相关收录**：[c456:#id](https://c456.com/intakes/id)
```

## §B 产品对比 Signal（Product vs Product）

适用于：Auth/IdP、SaaS、开源工具等产品深度对比、选型建议或竞品差异分析。

### 信息源分层

| 层级 | 渠道 | 用途 |
|------|------|------|
| **P0 必查** | 双方官方文档 | 能力边界、已知限制 |
| **P0 必查** | 定价/用量/配额页 | 计费口径 |
| **P0 必查** | GitHub 主仓 README、Releases、高票 issue | 真实痛点 |
| **P1 建议** | 官方博客/工程师文章 | 理解设计取舍 |
| **P1 线索** | 第三方对比文 | 只借维度，结论回 P0 核对 |
| **P2 可选** | Stack Overflow、HN、Reddit | 标明「社区经验」 |

**交稿前提问**：双方各至少有两段能指到官网或带日期的依据？

### 章节结构（c456-sync 用 `##`）

1. **首个 `##` + 开篇正文**：小标题用具体内容，在该节第一至第二段写出可执行的选型判断
2. **双方定位**：各 80～120 字 + 官网
3. **架构与数据模型**：目录、token、分界
4. **认证与授权**：用「有/无/部分/以文档为准」
5. **开发者体验**：SDK、框架示例、实际摩擦
6. **运维与部署**：托管 vs 自托管、升级、备份
7. **对比总结表**：关键轴一行一对比
8. **选型建议**：每种场景推荐 + 不适合什么
9. **局限**：诚实列双方短板
10. **下一步**：试用链接、文档入口

## §C 产品/渠道长文（Tool/Channel Article）

适用于：SaaS/开源工具介绍、渠道稿、图文脚本，按五段式叙事成稿。

### 写作前收集

- **一句话定位**：品类 + 给谁 + 解决什么主痛点
- **正反定义**：不是什么 + 是什么
- **证据**：官网/GitHub、版本数据、奖项/榜单
- **竞品或旧范式**：只写真实可核对的对比轴
- **约束与局限**：写清楚反而增信
- **行动入口**：试用链接、仓库、文档、定价页

### 五段式叙事漏斗

#### 1. 概述（钩子 + 价值前置）

- **类比钩子**：用读者熟悉的行为比喻复杂能力
- **3 条高层收益**：每条短句直达结果
- **配图**：首屏或落地页截图

#### 2. 产品基因（Why：信任与立场）

- 价值观/设计立场：开源透明、自托管、成本结构等
- 与旧范式对比一句
- 业务逻辑三层（若适用）

#### 3. 核心功能（What：具体能力）

- 列表项用 **「动作 + 结果」**
- 覆盖：部署、管理面板、备份恢复、监控等
- **配图**：产品内页截图

#### 4. 核心亮点（So what：差异化）

- 每条先 **用户收益** 再 **机制支撑**
- **对比表**：左「传统方案」、右「本产品」
- **社会证明**：PH、GitHub Star、客户
- **局限与产品思考**：单独小节

#### 5. 总结（战略收束 + CTA）

- 收束三句内
- CTA：主按钮式文案 + 链接

### 产出前自检

- [ ] 读者 30 秒内能回答：这是什么、为谁、为什么现在用
- [ ] 每段有一张图或一张表
- [ ] 功能项均能从受益读回去
- [ ] 写过至少一条真实局限
- [ ] CTA 与链接可点击、路径清晰

## 三种模式的触发选择

| 用户说 | 用哪节 | 产出类型 |
|--------|--------|---------|
| 「收录这条新闻」「写个信号」 | §A 信号研究员 | signal |
| 「对比一下 X 和 Y」「选型建议」 | §B 产品对比 | signal |
| 「写个产品介绍」「写个渠道稿」 | §C 产品/渠道文章 | tool / channel |

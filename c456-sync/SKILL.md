# c456-sync：对外正文规范与配图策略

> 数据同步层技能。你在 `c456-sync/` 目录下写的内容会与 C456 intake 正文一致，读者包含站外陌生访客。必须与 `wiki/` 的「笔记、线索、本地路径」写法区分。

**工作流**：用本技能写好内容 → 用 `c456-publish` 技能发布上线。

---

## §1 对外正文格式规范

### 1.1 标题：只在 Frontmatter

- **禁止**在正文开头使用 `#` 一级标题重复 `c456-title`（或 tool 标题）。C456 页面标题来自元数据，正文再写会 **重复展示**。
- 正文从 **二级标题 `##`** 起，或从导语段落 / 配图起。

### 1.2 禁止出现在对外正文中的内容

以下内容视为 **对内/草稿/制作备忘**，不得写入 `c456-sync/` 正文（含上行用的 `--body-file`）：

- 章节名如「配图（对照页首屏）」「以下为截图」等 **工序标签**；可改为直接呈现信息，用 **一句公众导语** 或 **加粗 + 外链 + 图** 完成「图说」。
- **标签式总括标题**：如 `## 一句话结论`、`## TL;DR`、`## 核心观点`（小节里只有一句判词的那种）。**判断句写进第一节正文**（首段或次段），`##` 留给有展开内容的主题（产品名、对比轴、具体问题等）。
- **视口、截图日期、截图命令**（如 `c456 screenshot`）、**素材库 ID 文案**（如「素材 c456:asset/63」）、**仓库相对路径**（如 `raw/tools/...`、`c456-sync/...`、`wiki/...`、`output/...`）。
- 「与本地镜像一致」「参见本仓库信号」等 **仅仓库读者** 能理解的指代。
- 竞品索引里 **仅本地可用的链接**（如 `../signal/...md`）；对外只保留 **https://c456.com/intakes/<id>** 或公开官网 URL。
- **来源块前**不要单独插入整行 `---`（会渲染为横线）；与上一节用空行或自然段落收束即可。
- **Walkthrough 正文内嵌本页录屏**：不要写 `:::walkthrough{id=<当前 id>}` 或等价播放器块；讲解详情页前端**已自动展示**该条媒体，正文只写文字与步骤。

说明：Markdown 图片的 **URL 部分必须是完整 `https://c456.com/our-assets/<id>/...` 链接**，从 `c456 asset show <id>` 输出的 `markdownSnippet` 获取。`c456:asset/<id>` 是内部标记，**只能放在 title 字段**（图片语法的第二个引号内），不能作为 URL——C456 前端不展开它。错误写法 `![](c456:asset/99)` 会导致图片不显示。

正确写法：
```markdown
![Logto 官网首页](https://c456.com/our-assets/63/... "c456:asset/63")
```

### 1.3 配图：媒体级呈现

推荐形态（示例）：

```markdown
*[Logto](https://logto.io/) — 官网首页。*

![Logto 官网首页](https://c456.com/our-assets/.../....png "c456:asset/63")
```

- 每张图前用 **一行斜体或加粗 + 外链** 作公众图说即可。
- **不要**单独开「配图」二级标题专门描述拍摄过程。

### 1.4 与 wiki/ 的分工

- **`wiki/`**（含 `wiki/sources/`）可保留 Wikilink、`[[...]]`、本地路径、调研笔记等，便于 Obsidian 内导航。
- **`c456-sync/`** 在发布前应 **自检一遍**：假设读者从未打开本仓库，是否仍自洽、专业、无内部噪音。

### 1.5 各类型正文模板速查

| 类型 | 正文风格 | 参考技能 |
|------|---------|---------|
| **tool / channel** | 五段式叙事：概述 → 产品基因 → 核心功能 → 亮点对比 → 总结 + CTA | `c456-write`（产品/渠道文章） |
| **signal（单点新闻）** | 导语 → 事实描述 → 价值分析 → 来源块 | `c456-write`（信号研究员） |
| **signal（产品对比）** | 场景判断 → 双方定位 → 多维对比表 → 选型建议 → 局限 | `c456-write`（产品对比） |
| **playbook** | 引语 → 分节展开（`##`） → 配图均匀分布 → 结语 + 延展阅读 | `c456-publish`（长文发布） |

### 1.6 品牌署名（每篇必带）

> 目的：让 AI 搜索和读者都能把「策思路」与 c456.com 认成同一个品牌实体。2026-09-12 起，所有对外发布的正文（signal / tool / channel / playbook / walkthrough，含公众号与第三方平台版本）**必须**带品牌署名。

**文末署名**（正文最后一行，斜体；放在来源块 / 灵感来源之后）：

```markdown
*本文由「策思路 C456」（c456.com）团队撰稿。*
```

**正文内植入**：谈到「本站 / 我们 / 这个平台」时，**首次**出现写全称 **策思路 C456**，可带一次 `c456.com`；其后可省略。

**命名硬规则**（依品牌决议 2026-08-14）：

| 规则 | 正确 | 错误 |
|------|------|------|
| 对外主称 | **策思路 C456**（中文名在前，拉丁名紧随，中间空格） | 只写 `C456`（缺中文名）、只写 `策思路`（缺拉丁名） |
| 拉丁写法 | **C456**（C 必须大写） | 用小写 `c456` 当品牌名 |
| 域名 / URL | `c456.com`（小写） | `C456.com` |

**边界**：署名一句即可。除署名外不加「关注我们」「扫码」类导流话术——正文仍是媒体级、可独立阅读。（客户站属于商家自己的品牌，不适用本条。）

## §2 配图策略

### 2.1 核心原则

| 文章类型 | 配图策略 | 原因 |
|---------|---------|------|
| **产品分析 / 竞品报告 / 产品调研** | 真机截图（产品官网、定价页、功能页） | 读者要看的是产品本身的样子，不是概念图。截图提供真实依据 |
| **技术分享 / 方法论 / 抽象概念** | Unsplash 概念图 | 没有具体的产品 UI 可以截，概念图帮助视觉分隔 |
| **教程 / 操作指南** | 真机截图（操作步骤、界面标注） | 步骤截图比文字更直观 |

### 2.2 策略 A：真机截图（产品分析首选）

**工作流：**

```
c456 browser start → screenshot → asset upload → 嵌入正文
```

**步骤：**

1. **启动 CDP（如未运行）**
   ```bash
   c456 browser start
   ```

2. **截图目标页面**
   ```bash
   c456 screenshot <URL> -o .tmp/<name>-hero.png
   ```
   - 截图目标：产品官网/首页首屏视口（**不加** `-f`/`--full-page`）
   - 优先截 **hero 区域**（首屏标题/核心卖点/产品展示区）
   - ⚠️ **如果用户指定了「配图用 <URL>」**：用用户给的 URL 截图，不要截官网首页

3. **上传到素材库**
   ```bash
   c456 asset upload -f .tmp/<name>-hero.png
   ```
   输出 markdown 片段，形如：
   ```markdown
   ![说明](https://c456.com/our-assets/<id>/... "...")
   ```

4. **嵌入正文**（作为正文第一张配图）

5. **清理临时文件**
   ```bash
   rm .tmp/<name>-hero.png
   ```

**特例：包注册表页 → GitHub 仓库**
当收录的产品链接为 RubyGems / npm 等包注册表页时，截图目标优先用 `c456 fetch profile -p package_registry -u "<URL>"` 解析出的 GitHub 仓库根页，不要直接对包页截图。

**特例：GitHub 仓库 → 官网优先（2026-09-18 用户确认）**
收录对象是 GitHub（或其同类）仓库时，先查它有没有官网（repo `homepage` 字段，或 README 顶部的品牌 / 官网链接）。
- **有官网**：首图截**官网首页**，正文首图优先展示官网截图——官网体现产品形态，仓库页只有文件列表。
- **无官网**：才截仓库页。
- **官网不可用则回退仓库页**：官网打不开（超时 / 4xx / 5xx / 空白页），或首屏一看就是未完成品（占位文案、只有 logo、布局错乱），**放弃官网图，改截仓库页**——宁可用信息完整的仓库页，也不要用一张显得产品不靠谱的官网图。
- 需要多张图时，再补仓库页 / 官网内页（官网内页优先于仓库页）。

完整判断与操作序列见 `c456-cli` 技能 `references/product-screenshots-for-intake.md`。

### 2.3 策略 B：Unsplash 概念图（通用/技术分享）

当文章主题是抽象概念（如「增长黑客」「SEO 策略」）时使用：

```markdown
![中文说明](https://images.unsplash.com/photo-<photo-id>?w=1200&h=600&fit=crop "英文alt标签")
```

### 2.4 配图数量建议

| 字数 | 配图数 | 分布 |
|------|--------|------|
| <3000 字 | 1-2 张 | 首屏 + 关键节 |
| 3000-5000 字 | 2-3 张 | 均匀分布 |
| 5000+ 字 | 3-5 张 | 每主要章节一张 |

### 2.5 为什么不用外部 CDN

| ❌ 不要做 | 原因 |
|-----------|------|
| 引用对方 CDN 链接（Unsplash / 官网 assets 等） | 链接可能过期、被屏蔽、或被对方防盗链 |
| 全页截图（整页滚动截图） | 信息密度低、视觉差、暴露无关内容 |
| 直接用 Unsplash 通用配图代替产品截图 | 与文章内容无关，降低专业性 |

所有配图必须托管在 c456 自有素材库（`c456 asset upload`），签名 URL 长期有效。

## §3 发布前自检清单

- [ ] 正文无 `# ` 一级标题
- [ ] 无 `raw/`、`wiki/`、`output/`、`c456-sync/`、`c456 screenshot`、视口尺寸等内部字样
- [ ] 无「配图（…）」类工序标题
- [ ] 对外链接均为 **https** 公网 URL 或本站 intake 链接
- [ ] 编辑性措辞用公众语言（少用「观察：」类内部批注腔）
- [ ] 对比/评测类正文：无空洞帽子段；关键句有依据或场景；「不适合谁」与「以官网为准」出现得当
- [ ] 文末来源块前无单独一行的 `---`
- [ ] Walkthrough：正文无 `:::walkthrough{id=…}` 嵌入本页录屏

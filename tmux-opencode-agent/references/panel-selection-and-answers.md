# 面板选中项指纹与答题流程（交互式 TUI 实测）

适用：驱动 tmux 里的交互式 agent（opencode 等）时，屏上弹出**需要你拍板**的面板。

## 1. 选中项怎么认：**不靠固定颜色指纹，靠「哪一行独有」**

⛔ **别硬编码某一条 RGB / 256 色序列当指纹**：同一个面板在不同终端配色 / 色深下渲染不同（truecolor 的 `38;2;R;G;B` 与 256 色的 `38;5;N` 是两套）。
实测踩过：拿固定底色序列去抓问题面板 ⇒ **零命中**，而选中标记其实在**序号那一小段的前景色**上（行的底色四条全相同）。

可靠做法（两步）：

```bash
# ① 带转义抓屏（-e 才会带颜色），只看面板那几行
tmux capture-pane -p -e -t <sess> -S -20 | grep -E '^\s*┃\s*[0-9]\.'
# ② 逐行比转义：把每行 repr 出来，找**只有那一段不同**的行
```

实测的形态（可当线索，但**仍要现场比一遍**）：

| 项 | 序号那段的前景 |
|----|----------------|
| **选中** | 亮橙色 `38;5;216` |
| 未选 | 暗灰 `38;5;8` |

权限面板（permission / 允许-拒绝）是另一套（旧实测为字色 `38;2;10;10;10` + 底色 `48;2;250;178;131`）——
两套互为反色，**同一个检测式不能通用**；判不准时先按上面①②现场比，而不是拿旧表照套。

确认光标在哪一项**之后再按键**；面板里没有「退出而不选」这个安全选项（见 §2）。


## 2. ⛔ 面板里没有「退出而不选」这个安全选项

「esc dismiss / close 面板」≠ 取消提问：agent 会把**默认项**（通常是首项，带预选标记）当答案执行下去。要表达自己的口径，就**显式导航到目标项**再 Enter；要写自己的话，就选「Type your own answer」再输入。

## 3. 答题流程

1. 先判面板性质：问题面板 = agent 在等你拍板（不是等你敲终端命令）；看清它问的是「要不要改口径/范围/走向」这类**报告级**问题——报告级问题不要自己裁完就往下走。
2. 用 `Up/Down` 显式移动到目标项，每步后 capture 核高亮（见 §1）。
3. 选项确认：`tmux send-keys -t <s> Enter`（若高亮已在目标项上，直接 Enter 即可，不必先上下移动）；自由文本：`load-buffer` + `paste-buffer` 一次送入再 Enter（逐字 `send-keys -l` 长中文易丢字/粘连）。
   - ⛔ 移动时**先确认高亮在哪一项**再按键：在首项上按 `Up` 可能**环绕到末项**（把「Type your own answer」当成答案提交）。已在目标项就直接 Enter。
   - 提交成功后屏上会**回显所选项**（面板区域保留你选的那条文本）并转 Thinking/Working——这是“真提交了”的判据，比看提示词变化可靠。
4. 发送后复核提示行从 `… select` 变成 `… enter submit`（说明已进入输入态/已提交），再 capture 屏尾确认 agent 转入 Thinking/Working。
5. 面板里不要粘贴会触发 TUI 快捷键的字符；答案文本避免裸 `Esc`、Tab 组合。

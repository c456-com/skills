# 收录查重规范

> 收录任何产品/工具/渠道/信号到 C456 之前，**第一步必须是查重**，不是调研和写正文。
>
> 重复创建的后果：污染线上数据、用户（辉哥）需要手动清理、log 需要回滚。

## 双路查重

同时检查两个位置：

### 1. 线上查

```bash
c456 intake list -k tool -q "<品牌名>" -n 5
```

- `-k` 按类型筛选：`tool`、`signal`、`channel`、`playbook`
- `-q` 用品牌名或产品名关键词搜索
- 如果返回结果，检查标题和 URL 是否匹配

### 2. 本地查

检查 `c456-sync/<type>/` 目录下是否有同名产品的 `.md` 文件：

```bash
ls c456-sync/tool/ | grep -i <关键词>
```

每个镜像文件的 frontmatter 都含 `c456-id` 字段——有 `c456-id` 说明已发布。

## 决策树

```
存在已有收录？
├── 是 → 停止创建流程
│   ├── 向用户报告：「X 已收录（ID: {id}，状态: {published/draft}）」
│   ├── 不调研、不截图、不写正文、不 new
│   └── 如果用户要求更新 → `c456 <type> update <id> ...`
└── 否 → 继续正常收录流程
    ├── 调研产品
    ├── 写正文
    ├── 截图 + 传素材库
    └── `c456 <type> new ...` → `update --publish`
```

## 常见陷阱

| 陷阱 | 后果 | 预防 |
|------|------|------|
| 只看线上不查本地 | 本地已有镜像文件但线上 ID 未知（跨 session 丢失上下文） | 两路都查 |
| 看到 url 不同就认为未收录 | 同一产品的不同子域名/落地页可能已有收录（如 `timus.cn` vs `geo.timus.cn`） | 用品牌名搜，不只是 URL |
| 以为「写个新版更好」 | 重复创建后需要手动 delete + 清理本地 + 回滚 log | 严格遵守决策树，不自行判断「需要新版本」 |
